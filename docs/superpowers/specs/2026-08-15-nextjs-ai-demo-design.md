# Next.js `ai_demo` Project Design

## Objective

Create a clean, modern Next.js project directly in the existing `ai_demo` directory. The project will be ready for agentic development with Codex and for incremental UI development with shadcn/ui, without adding product features prematurely.

## Project Scope

The initial result is an infrastructure-only starter. It includes the framework, styling, linting, UI-system configuration, version control, and project guidance for Codex. It does not include an AI SDK, database, authentication, business logic, sample UI components, or a test framework.

## Technology Stack

- Next.js 16.2.12, installed through the latest stable `create-next-app` release
- React and React DOM versions selected by that stable scaffold
- TypeScript
- App Router
- Tailwind CSS v4
- shadcn/ui using Base UI primitives
- shadcn Nova style with a neutral, CSS-variable theme
- Lucide icons
- ESLint
- Turbopack
- pnpm
- Git

React Compiler will remain disabled.

## Project Layout and Conventions

- Scaffold directly into the current directory rather than creating a nested `ai_demo` directory.
- Place application code under `src/`.
- Use `@/*` as the import alias.
- Keep the standard Next.js starter page.
- Prefer React Server Components. Add Client Components only when browser-side state, effects, or event handling require them.
- Add shadcn components individually when a feature needs them rather than preinstalling a component collection.

## shadcn/ui Initialization

Initialize shadcn/ui after the Next.js scaffold. The initialization will create and configure:

- `components.json`
- CSS-variable theme tokens in the global stylesheet
- `src/lib/utils.ts` with the `cn` utility
- aliases for components, UI components, utilities, hooks, and library code

No sample shadcn component will be added during initial setup. Successful CLI project inspection will confirm the integration.

## Codex Agent Guidance

Keep the root `AGENTS.md` generated by `create-next-app` as the single root project-instruction file. Preserve the Next.js-managed section and append project-specific instructions outside its managed comment markers.

The appended guidance will require agents to:

- use pnpm exclusively;
- follow TypeScript and App Router conventions;
- consult the version-matched Next.js documentation bundled in `node_modules/next/dist/docs/`;
- prefer Server Components unless client behavior is necessary;
- use the configured shadcn/ui Base UI foundation;
- explain the need for new production dependencies;
- keep secrets in uncommitted environment files; and
- run lint and a production build before declaring implementation work complete.

Nested `AGENTS.md` files are unnecessary until a future subdirectory needs genuinely different instructions.

## Runtime and Data Flow

The starter has no application data flow. Requests render through the App Router using the standard root layout and starter page. No API routes, external services, persistent state, or client-side data fetching will be introduced.

## Error Handling

Use Next.js default development and runtime error handling. Custom `error.tsx`, `not-found.tsx`, or `loading.tsx` files are outside the initial scope because no product routes or asynchronous workflows exist yet.

## Verification

Setup is complete only when all of the following succeed:

1. pnpm dependency installation completes.
2. ESLint reports no errors.
3. A production Next.js build completes.
4. The shadcn CLI recognizes the project configuration.
5. Git status contains only the intended scaffold and configuration files before the initial project commit.

No unit or end-to-end test framework will be installed in this infrastructure-only starter. Feature work should introduce tests when it adds behavior worth testing.

## Explicit Non-Goals

- AI provider or AI SDK integration
- Authentication or authorization
- Database or ORM setup
- Deployment configuration
- CI/CD configuration
- Sample shadcn components or demo screens
- Custom branding or visual design
- Unit, integration, or end-to-end test tooling
